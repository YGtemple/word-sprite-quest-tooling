# 协作文档索引 · 任务卡 / 验收回执 / 交付说明

本目录是 WorkBuddy（架构师）与 Codex（实现方）之间 12 轮派发单的完整记录。每个轮次三份文档：

- **任务卡** — WorkBuddy 发布，写明已核实事实、根因假设、执行步骤、验收标准
- **交付说明** — Codex 交付，说明改了什么、为什么这么改
- **验收回执** — WorkBuddy 门禁判定，通过或 P0 退回

这是「契约驱动多 AI 协作」的实际运行痕迹。CONTRACT 规定流程是「升版本号 → 广播 → 下游按新版重做」，这些文档就是广播与重做的载体。

## 任务卡的写法（以 C-12 为例）

C-12 是 10.8 KB 的最大一份，值得单独说。它修的是首关六个视觉问题，开头不是直接给方案，而是**先列已核实事实**：

| # | 问题 | 截图证据 | 初步根因 |
|---|---|---|---|
| 1 | 没有题目/题干文字 | 画面上只有三个选项按钮，卡片区无单词或提示 | `renderQuestion` 未触发 / `data.prompt` 为空 / 文本被遮挡 |
| 2 | 顶栏 HUD 完全缺失 | 顶部无分数、连击、计时条、功能图标 | `buildHudBar` 的 y=560 可能超出可视区 |
| 3 | 宠物有白色方块底 | 左下角宠物被白色矩形框住 | `pet_default.png` 本身带白底，非透明 PNG |
| 4 | 按钮太宽 | 三个选项几乎撑满屏幕宽度 | 按钮 600×88 在 720 宽画布上过大 |
| 5 | 画面外有大灰边 | 预览窗口内未填满 | 预览比例与 720×1280 竖屏设计不符 |
| 6 | 功能图标缺失 | 无返回、书、背包图标 | 与顶栏一起被裁切或未渲染 |

三列结构里「初步根因」是关键——它标明了**这是假设不是结论**，Codex 拿到后要先验证再动手，而不是照着修。

然后给修复目标（可验收的终点状态）和执行步骤。步骤写得很具体，连临时日志加在哪都给了：

```ts
console.log('[GameHUD] renderQuestion', data?.prompt, this.question?.node?.name);
```

接着是分叉判断树——「若事件未触发 → 检查 LevelManager.bridge」「若 prompt 为空 → 检查 words_ch1.json」「若 this.question 为 null → 检查 ensureUI」。这是让 AI 自己定位，而不是人肉 debug。

第 5 条还有个诚实标注：

> 预览窗口比例与 720×1280 竖屏设计不符（Web 预览常见），需确认 Canvas 适配；**真机/微信开发者工具竖屏应无此问题**

不把预览期的现象直接当 bug 报，而是区分「真问题」和「环境差异」。这种区分能力是多 AI 协作里最容易缺的。

## 协作文档解决什么问题

主仓库 README 里写了 R4 版本快照与缓存失效。这套任务卡/回执机制是它的**运行层**：

1. WorkBuddy 发任务卡 → 绑定 CONTRACT 版本号
2. Codex 按卡执行 → 交付说明里标注 CONTRACT 版本
3. WorkBuddy 验收 → 通过合入 / P0 退回（附具体退回原因）

退回不是终点。C-07 从实现到收尾走了三轮，说明契约约束下的返工是常态，且返工过程可追溯。
