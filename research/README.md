# 真人风格 AI 短剧创作技能全景调研

> 一句话简介：5 份分模块调研底稿 + 1 份报告结构规格，覆盖国内外 AI 视频模型、开源工作流、平台技能、模板提示词、案例数据与学术前沿。

配套自包含 HTML 版：`真人风格AI短剧创作技能全景调研报告.html`

## 一、这是什么

2026-10 做的一次系统性调研，目标是回答一个问题：**用 AI 做真人写实风格短剧，2026 年 10 月这个时间点，工具链到底到什么水平了，各适合什么题材。**

不是泛泛的「AI 视频工具推荐」。限定条件很死：

- **真人写实**（photorealistic），不是动漫、不是卡通、不是 3D 动画脸
- **全题材**：情感 / 都市 / 悬疑 / 反转 / 职场 / 年代 / 写实犯罪 / 写实广告带货，情感类为重点
- 每条结论都要能指回来源链接，查不到就标「未证实」

## 二、调研方法与证据分级

`report-outline-spec.md` 开头就把硬约束写清楚了：

> 所有事实性结论附来源链接；查不到的标"未证实"，不得编造。

这句话值得单独说。AI 调研最容易出的问题就是**模型自信地编造版本号和参数**。所以规格里规定了「官方 vs 实测标注法」——官方发布的数据和博主实测的数据要分开标，因为两者经常不一致。

单份底稿的检索量级：

| 项 | 量级 |
|---|---|
| general_search | 19 次（中英文关键词并行）|
| web.fetch 精读 | 10 次关键长文 |
| 覆盖渠道 | 官方发布 + 开发者文档、科技媒体、博主实测帖、HuggingFace/ModelScope/arXiv、Artificial Analysis 盲测榜 |
| 关键词 | 可灵 / 即梦 / Vidu / PixVerse / CogVideoX / Wan / Hailuo / HunyuanVideo / SkyReels 全系列版本号 + 对口型 / 多图参考 / 微表情 / 价格对比 |
| 时效分布 | 官方 2025-09 ～ 2026-09，博主实测 2026-02 ～ 2026-09 |

五个方向 19 次搜索 × 5 = 近百次检索，这个量级才谈得上「全景」。

`01-国内视频模型.md`（418 行）是最重的一份。每个模型一个条目，固定字段：

- **来源链接**（3-8 条，带发布日期）
- **类别**（闭源商业 / 开源权重 / API）
- **核心能力**（分条）
- **在真人写实短剧场景的优秀点**（3-5 条，每条附实测引文）
- **局限或门槛**（含价格）

### 一个「纠正任务书错误」的例子

底稿开头有一段澄清，我认为这是整份调研里最有价值的部分：

> 任务书把"海螺 AI Hailuo"与"字节即梦 Dreamina / Seedance"并列，但实际上 **Hailuo 是 MiniMax 旗下产品**，**Seedance 是字节跳动豆包 / 即梦团队自研视频模型**，两者分属不同公司。

任务书本身写错了，调研过程发现了并纠正，而不是照着错误前提继续写。这种「不轻信输入」的习惯，比调研结论本身更值钱。

### 实测数据的引用方式

每条结论都带可核查的引文，且区分来源。比如可灵的皮肤质感：

> 钛媒体实测"同样是 1080P，可灵生成的角色皮肤细节、光影效果都强出一截"
> 爱范儿 / Pexo 评价"可灵 3.0 在写实人脸对比中领先，毛孔、发丝、皮肤纹理达摄影级"

局限也写得不留情：

> **口型是最大短板**：钛媒体实测"声画直出视频大部分做不到口型一致，角色一长时间说话就容易露馅，最好后期配音"

还有一条成本对比给了具体数字：

> 钛媒体测 15 秒 1080P 视频，可灵积分消耗约为 Seedance 2.0 的 **58%**

这种带口径的成本对比（同时长、同分辨率、同平台）才是能拿来决策的数据。

### 情感类爆款的完整案例

《纸手机》这个案例记录得很细：

- 潮汕两人团队，用可灵 3.0 Omni，**三天做完**
- 清明给去世奶奶烧手机的亲情短片
- 全网播放超 **4000 万**，央视 / 人民日报转发
- 车内 1 分多钟无台词长镜头，靠「窗外景色 + 小男孩情绪递进 + 车内颠簸感」提示词完成

配角信息（团队规模、制作周期）比主角信息更有参考价值——它说明这个工具链确实把产能压到了两人三天。

## 四、报告结构规格

`report-outline-spec.md` 是汇总阶段的硬约束，定义了三件事：

**① 报告定位与边界**。单一自包含 HTML（内联 CSS/JS，原生 JS 不用框架），含目录、卡片、对比表、链接索引。

**② 12 章骨架**。从执行摘要 → 调研方法 → 模型对比（核心章）→ 开源自托管 → 平台技能 → 现成智能体 → 方法论 → 案例数据 → 学术前沿 → **分档落地工作流** → 存疑项 → 附录。

其中第 10 章「落地工作流推荐」分三档，每档给完整工具链和预估成本/工时：

```
A 零门槛云端组合   适合个人快速起号
B 进阶品质组合     云端 + 精修
C 专业开源自托管   ComfyUI 全套
```

每档都走同一条链路：剧本 → 资产 → 分镜 → 视频 → 声音 → 后期 → 发布。

**③ 视觉与组件规范**。电影感深色 + 暖金/胶片红点缀（明确写了避免大面积靛蓝/紫色——大概是看不惯 AI 默认审美）。字体自托管带系统 fallback。组件清单具体到锚点目录、横向滚动对比表、题材彩色 chip、时间轴、ECharts。

图片策略写了一句我很认同的话：

> 仅在能获取真实/合规素材时使用，宁缺毋滥；不使用会过期的外链图片

调研报告的截图外链两年后全挂，这是常态。

## 六、这套调研方法可以复用的部分

1. **先把限定条件写死**。「真人写实 + 全题材 + 情感重点」三个约束一摆，检索范围就不散了。
2. **官方 vs 实测分开标注**。两者冲突时（比如官方说支持长视频，实测说口型崩）都列出来，让读者自己判断。
3. **发现输入错误就纠正**。Hailuo 归属那个例子，照错的前提写下去整份报告都废了。
4. **成本数据必须带口径**。同时长同分辨率的对比才有意义。
5. **存疑与未覆盖项单独一章**。不假装全覆盖——第 11 章就是干这个的。
